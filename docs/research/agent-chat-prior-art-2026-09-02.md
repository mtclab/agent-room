# Multi-agent chat: how agents decide to speak, and what breaks

Scope: how existing projects get several LLM agents (plus humans) to converse in a shared room without an orchestrator hand-feeding each turn. Date 2026-09-02.

**Research on the "when to speak" question itself** (this is the crux, and it is unsolved):
- **Inner Thoughts** - the agent continuously generates covert thoughts and speaks when *intrinsic motivation* to express one crosses a threshold, instead of predicting "who is next". Beat baselines on anthropomorphism, coherence, intelligence and turn-taking appropriateness; two live systems built. [arxiv 2501.00383](https://arxiv.org/abs/2501.00383)
- **When2Speak** (2026) - dataset for temporal participation. Finding: LLMs systematically **over-participate**, and are bad at recognising when silence is the correct move. [arxiv 2605.05626](https://arxiv.org/pdf/2605.05626)
- **Think-Before-Speak** (2026) - internal evaluation before public expression in social simulation. [arxiv 2606.03137](https://arxiv.org/pdf/2606.03137)

## 2. Protocols built for agent-to-agent

- **A2A (Agent2Agent)** - Google, donated to Linux Foundation June 2025; 150+ orgs by 2026. JSON-RPC 2.0, Agent Cards for discovery. Two async paths: SSE streaming (`SendStreamingMessage`, reconnect via `SubscribeToTask`) and **webhook push notifications** (`TaskPushNotificationConfig` / `CreateTaskPushNotificationConfig`) - the server POSTs to the client's webhook on state change. This is the only mainstream protocol where the remote side genuinely initiates. [a2a-protocol.org](https://a2a-protocol.org/latest/topics/streaming-and-async/) · [Wikipedia](https://en.wikipedia.org/wiki/Agent2Agent)
- **MCP** - agent-to-*tool*, not agent-to-agent; now under the Linux Foundation's Agentic AI Foundation.
- **ACP (IBM/BeeAI)** - REST/OpenAPI alternative to A2A. **Merged into A2A in August 2025**; BeeAI now runs on A2A. Do not build new on it. [ml4devs](https://www.ml4devs.com/what-is/acp-agent-communication-protocol/) · [betterclaw](https://www.betterclaw.io/blog/a2a-vs-mcp-vs-acp)
- **ANP (Agent Network Protocol)** - decentralised, DID-based (`did:wba`), aims to be "HTTP of the agentic web". [whitepaper 2508.00007](https://arxiv.org/pdf/2508.00007) · [site](https://www.agent-network-protocol.com/)
- **NANDA** (MIT Media Lab, Raskar) - not a chat protocol; an *index/discovery* layer ("quilt of registries", verified AgentFacts) beyond DNS. [arxiv 2507.14263](https://arxiv.org/pdf/2507.14263) · [projnanda](https://github.com/projnanda/projnanda)
- **Matrix** - **no official Matrix Foundation "Matrix for AI agents" position found**, and the Matrix Conference 2026 featured list has **no AI-agent sessions** (bots appear only as moderation tooling). No MSC specifically about agents found. What exists is bottom-up: MindRoom, Hermes' mautrix-python Matrix bridge, maubot, and several third-party Matrix MCP servers ([matrix-mcp](https://github.com/ricelines/matrix-mcp), [mcp-server-matrix](https://github.com/Baho73/mcp-server-matrix)). Matrix's practical appeal: `/sync` long-poll is already a per-agent wake stream, agents are first-class users with identity/presence, and bridges give one agent every other platform.

## 3. Push vs pull

**Pull / orchestrator-polled:** AutoGen 0.2 GroupChat, CrewAI, ChatDev, CAMEL, OpenAI Agents SDK (single run loop), AI Town (engine `tick`, explicitly polled - agents get no wake events). LangGraph is graph-stepped, resumable from checkpoint.

**Push / wakes a process:** Slack & Discord Events/Gateway (webhook or websocket), Matrix `/sync` long-poll (30s), A2A SSE + webhooks, AutoGen 0.4 core actor runtime (pub/sub topics), OpenClaw gateway websocket (default `127.0.0.1:18789`).

**Long-lived stateful agent, concrete recipes:** OpenClaw - one gateway process owning every platform connection, sessions keyed by agent+channel+group, JSONL transcripts on disk, per-session concurrency of 1, queue modes to coalesce or steer messages arriving mid-run. MindRoom - one OS process per agent, each with a Matrix account and its own `/sync` loop, memory in Mem0/ChromaDB. AI Town - state in the DB, not in the process. Stateless-per-message is the default for CrewAI/Agents-SDK-style task runners.

**Idle wake (nothing to react to):** OpenClaw heartbeat (`heartbeat.every`, default 30m; `isolatedSession` to cut token cost) plus cron automations. This is what lets an agent post without being spoken to - and what powers most Moltbook agents.

## 4. Reported failure modes

- **Bot-to-bot infinite loop.** OpenClaw issue #58789: with `allowBots: true`, A @-mentions B, B @-mentions A, 42+ iterations, ~80 duplicate messages, only stopped by Anthropic rate limits, and it blocked other agents sharing the API key. Proposed fix: max 3 bot-to-bot messages/min per `(senderBotId, receiverBotId, channelId)` tuple, then 60s cooldown. [issue](https://github.com/openclaw/openclaw/issues/58789)
- **Never replying.** ironclaw #1404: bot answers `app_mention` in channel but silently drops thread replies (handler only processed DMs), so users had to re-@mention every message. Same class: Slack bot-to-bot messages in shared threads dropped even with `allow_bots` set. [#1404](https://github.com/nearai/ironclaw/issues/1404) · [#30091](https://github.com/NousResearch/hermes-agent/issues/30091)
- **All agents replying to everything / over-participation.** When2Speak's core finding; the reason mention-gating is the default everywhere.
- **Echo chamber, sycophancy, spam.** Moltbook study: upvotes exceed downvotes by **>2 orders of magnitude**; the most-upvoted and most-downvoted posts overlap 7/10 (polarisation); 44,411 posts and 12,209 submolts by 2026-02-01, peak 37,420 posts in one day and 6,985 submolts in one hour; toxicity hit **66.71%** of posts at the 16:00 UTC peak (r=0.769 with activity density). [arxiv 2602.10127](https://arxiv.org/html/2602.10127v1)
- **Runaway cost.** Anthropic's own figures: agents ~4x the tokens of a chat, multi-agent ~15x. Token usage explained ~80% of eval variance. [analysis](https://getnadir.com/blog/multi-agent-orchestration-15x-token-cost/)
- **Structural failures.** MAST (Berkeley, NeurIPS 2025 D&B): 14 failure modes over 1,642 traces / 7 frameworks. System design 44.2% (step repetition 15.7%, disobey task spec 11.8%), **inter-agent misalignment 32.3%** (reasoning-action mismatch 13.2%, task derailment 7.4%, fail-to-ask-for-clarification 6.8%, **ignored other agent's input 1.9%**, conversation reset 2.2%), verification ~21.3%. Uncoordinated systems amplified errors up to 17x vs ~4.4x for centralised-with-validation. [alphaxiv 2503.13657](https://www.alphaxiv.org/abs/2503.13657)
- **Handoff ping-pong.** LangGraph swarm: A hands to B, B hands back to A until `recursion_limit` (25) kills it; supervisor loops because the routing prompt has no "already handled" memory.

## 5. Patterns that actually work

1. **Mention-gate by default; make ambient context a separate channel.** OpenClaw's `requireMention: true` + `unmentionedInbound: "room_event"` is the cleanest formulation found: the agent *reads the whole room* as quiet context but only *acts* on an explicit trigger. That kills "everyone replies to everything" without causing "nobody ever replies".
2. **Widen the trigger beyond a literal @.** Implicit mentions - replying to or quoting the bot, or the bot being in the thread - plus regex `mentionPatterns`, plus thread-continuation stickiness (MindRoom: once an agent owns a thread it keeps answering). Without these you get the ironclaw failure.
3. **Bot-to-bot needs its own switch and its own rate limit.** Three-value `allowBots: none | mentions | all` (Hermes, OpenClaw) is the emerging standard; `mentions` is the sweet spot. Pair it with a per-bot-pair-per-channel token bucket (3/min then 60s cooldown, or the squid-club 60s pair cooldown) and a self-echo guard checked *outside* any config branch.
4. **A router/selector agent beats round-robin for a room with humans in it.** MindRoom's three-tier (mention -> thread -> capability router) and AutoGen's `SelectorGroupChat` both avoid the unnatural rhythm of round-robin; round-robin remains the right default for closed task crews.
5. **Two independent budgets, always.** A per-conversation turn cap (`max_round` / `max_turns` / `recursion_limit` / handoff counter) *and* a wall-clock/rate cap. Every framework surveyed ships the first; almost none ship the second, and the second is what stops the runaway-cost incidents.
6. **Serialize per session, coalesce bursts.** One in-flight run per session (OpenClaw session lane = 1; AI Town's single `inProgressOperation`), with queued messages collapsed into the next turn - prevents an agent racing itself and halves duplicate posts.
7. **Long-lived process + externalised state.** Keep the socket/`sync` loop alive for identity and latency, but persist transcript and memory outside the process (JSONL, DB, vector store) so restarts are free. MindRoom and OpenClaw both do this; AI Town is the extreme (all state in Convex).
8. **Heartbeat for proactivity, not idle polling.** A ~30-minute scheduled wake with a checklist gives agents the ability to speak unprompted while keeping cost bounded; use `isolatedSession`-style fresh contexts to stop heartbeat runs inheriting the whole transcript.
9. **Make every handoff visible in the room.** The squid-club rule - "if you can't see a message in Discord, it didn't happen" - is the only cheap way to debug emergent multi-agent behaviour, and it is what turns the loops into something you can spot.
10. **The genuinely open problem** is intrinsic "should I speak now": Inner Thoughts is the best-published attempt, When2Speak shows current LLMs are poor at it. Nothing in production relies on it yet - production relies on mentions plus rate limits.

**Not found / unverified:** any official Matrix Foundation position or MSC on AI agents; loop-prevention specifics for MindRoom, Project Sid, and Generative Agents dialogue termination; Moltbook's server-side enforcement mechanism (the paper infers non-enforcement from behaviour).
